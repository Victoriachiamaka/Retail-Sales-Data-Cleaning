# 📊 Retail Sales Data Cleaning Project

## 📌 Project Overview
This project focuses on cleaning a raw, messy sales dataset using **Microsoft Excel** to prepare it for data analysis. 

The initial dataset was **generated by an AI model** specifically engineered with real-world data extraction errors—such as duplicate entries, broken text casings, rogue white spaces, and non-standard text dates—to simulate the challenges encountered during actual data projects.

---

## 🛠️ Step-by-Step Data Cleaning Process

Here is the exact step-by-step methodology applied to clean the raw data:

### 1. Data Safeguarding & Backup
* **Action:** Duplicated the initial messy file to keep an untouched copy of the original dataset.
* **Purpose:** Establishes a fallback "source of truth" to protect against corrupted steps and enable rapid auditing.

### 2. Eliminating Duplicate Records
* **Action:** Selected the complete data grid, navigated to the **Data tab**, and utilized the **Remove Duplicates** function.
* **Purpose:** Destroys accidental form double-submissions to ensure metrics like transaction counts are highly accurate.

### 3. Text & White Space Standardization (`=PROPER(TRIM())`)
* **Action:** Added cleaning columns utilizing a nested formula structure: `=PROPER(TRIM(Cell))`.
  * `TRIM()` stripped out invisible leading, trailing, and trailing internal double spaces.
  * `PROPER()` automatically normalized character casings (e.g., turning `" lapTOP "` into `"Laptop"`).
* **Purpose:** Fixes spelling and casing errors so matching customer names, genders, and categories align perfectly.

### 4. Data Privacy & PII Management (Data Minimization)
* **Action:** Identified the phone number column as **PII (Personally Identifiable Information)** and completely deleted those data fields from the working dataset since they were not required for the final analysis.
* **Context from Internship:** Drawing from my data protection and data privacy internship experience—where I studied data safeguarding protocols and compliance regulations—I applied the standard of data minimization. Since the phone numbers were non-essential for our analysis goals, dropping them entirely was the safest way to ensure privacy compliance.
* **Purpose:** Protects consumer privacy and adheres to security standards by keeping sensitive, non-essential personal identifiers out of the dataset.

### 5. Stripping Text Components via Find & Replace (`Ctrl + H`)
* **Action:** Addressed the text-heavy long date column (e.g., `"Friday, March 14, 2025"`) by pressing **`Ctrl + H`**. In the **Find what** field, day patterns followed by their structural space (e.g., `"Friday, "`) were targeted and replaced with an **empty** field.
* **Purpose:** Deletes descriptive day strings to isolate raw text-based date sequences (`"March 14, 2025"`).

### 6. Converting Text Dates to True Short Dates (`=DATEVALUE()`)
* **Action:** Because Excel still held the isolated string as text, a definitive calculation was required to convert the cell.
  * Applied the cell equation: `=DATEVALUE(Cell)` to convert text strings to Excel's backend date format.
  * Formatted the outputs via the **Number Dropdown** to read natively as a **Short Date**.
* **Purpose:** Converts static text into an active, functional date format that can be sorted chronologically during analysis.

### 7. Number & Currency Formatting Optimization
* **Action:** Audited numeric columns (such as Quantities and Sales Amount) to ensure they were locked down as clean integers and decimals, removing any hidden text characters.
* **Purpose:** Guarantees that analytical math operations can calculate total aggregates, sums, and averages perfectly without running into formatting faults.
